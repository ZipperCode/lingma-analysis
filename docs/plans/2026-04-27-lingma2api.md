# Lingma2API Implementation Plan

> 说明（2026-04-27）：
> 本计划基于旧的 `.lingma` 运行态凭据边界，现已被 [2026-04-27-lingma2api-project-auth.md](/Users/Zipper/Github/lingma-analysis/docs/plans/2026-04-27-lingma2api-project-auth.md) 取代。

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** 在仓库内新增一个基于 Go 的 `lingma2api` 最小 OpenAI 兼容代理，支持模型列表、流式/非流式聊天、凭据热重读、会话管理与最小管理接口。

**Architecture:** 新实现放在独立目录 `lingma2api/`，使用 Go 标准库搭建 HTTP 服务，核心逻辑放在 `internal/proxy`，HTTP 路由放在 `internal/api`。远端传输首期严格走 `curl` 子进程，凭据来源与签名逻辑对齐 `lingma_remote_api.py`，并通过内存会话与模型缓存提供最小服务化能力。

**Tech Stack:** Go 标准库、`curl` 子进程、手写最小 YAML 解析、基于 `httptest` 的 API 测试。

**Constraints:** 当前工作区缺少 `go` 可执行文件，且本地 Docker daemon 不可用，因此计划中的测试与格式化命令是目标验证命令；本轮实现后仍需在具备 Go 工具链的环境中实际执行。
